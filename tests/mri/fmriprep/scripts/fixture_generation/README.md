# Regenerating the real-data test fixture

**You do not need any of this to run the tests.** To run the real-data test, download the published fixture instead:

```bash
bash ./tests/mri/fmriprep/scripts/real/step_1_figshare_download.sh
bash ./tests/mri/fmriprep/scripts/real/step_2_run_test.sh
```

The scripts in this directory reproduce the published fixture from scratch. They are kept for reproducibility and for the case where the fixture has to be rebuilt (for example after a change to `exclude`, to the session/run layout, or to `data_mode`).

## What the fixture is

| Item | Value |
| --- | --- |
| Published archive | `ds006319_fmriprep-1.2.1_minimal.tar.gz` |
| DOI | [10.6084/m9.figshare.32857559.v1](https://doi.org/10.6084/m9.figshare.32857559.v1) (CC BY 4.0) |
| md5 | `7f4ec67fb6e73239d3e5dc1066ef8f55` |
| Size | 1,769,324,197 bytes (~2.9 GB unpacked) |
| Source dataset | OpenNeuro [ds006319](https://openneuro.org/datasets/ds006319/versions/1.0.1) v1.0.1 (CC0), doi:10.18112/openneuro.ds006319.v1.0.1 |
| Preprocessing | fMRIPrep 1.2.1, Docker image `poldracklab/fmriprep:1.2.1` |
| FreeSurfer | 7.4.1 (`freesurfer-linux-ubuntu20_x86_64-7.4.1-20230614-7eb8460`), `recon-all -all` on `sub-S1_ses-anatomy_T1w.nii.gz` (see `step_2_run_freesurfer.sh`) |

The published fixture was built with FreeSurfer 7.4.1 run outside the container, and its output passed to fMRIPrep as `derivatives/freesurfer`. Rebuilding with a different FreeSurfer version changes the surfaces and the registration, so the golden master has to be regenerated together with the rest of the fixture; record the version you used when you republish.

## Requirements

- `datalad` (to fetch the raw BIDS dataset from OpenNeuro)
- FreeSurfer with a valid license file
- Docker (for fMRIPrep 1.2.1)
- Python with `h5py` and the bdpy dependencies

The full run needs roughly 60 GB of free disk space and several hours, dominated by `recon-all` and fMRIPrep.

## Steps

```bash
cp ./tests/mri/fmriprep/scripts/fixture_generation/_fs_env.sh.example \
   ./tests/mri/fmriprep/scripts/fixture_generation/_fs_env.sh
# edit _fs_env.sh: FREESURFER_HOME and FS_LICENSE. It stays local (gitignored).

bash ./tests/mri/fmriprep/scripts/fixture_generation/step_1_download.sh          # datalad: raw ds006319
bash ./tests/mri/fmriprep/scripts/fixture_generation/step_2_run_freesurfer.sh    # recon-all
bash ./tests/mri/fmriprep/scripts/fixture_generation/step_3_run_fmriprep.sh      # fMRIPrep 1.2.1 in Docker
bash ./tests/mri/fmriprep/scripts/fixture_generation/step_4_prepare_gm.sh        # golden master (~2.4 GB)
bash ./tests/mri/fmriprep/scripts/fixture_generation/step_5_build_minimal_bundle.sh  # minimal subset -> tar.gz
```

`step_5_build_minimal_bundle.sh` writes `ds006319_fmriprep-1.2.1_minimal.tar.gz`, which is the archive published on figshare.

## Why the subset is what it is

The test uses `exclude={"session/run": [[1, 2, 3, 4, 5], [1]]}`, which is positional:

- `ses-SoundTest01` (session index 0): all five runs are excluded. The session directory must still exist, with an empty `func/`, so that the session indices line up. `step_5_build_minimal_bundle.sh` keeps it with a `.gitkeep` so it survives `tar`.
- `ses-SoundTest02` (session index 1): `run-01` is excluded, but its `desc-confounds_regressors.tsv` and `events.tsv` are still needed for run discovery and event pairing. `run-02` and `run-03` are the runs the test actually loads.

Only `space-T1w_desc-preproc_bold` is included, because the test runs in `volume_native` mode. Raw `events.tsv` and `bold.json` are included because fMRIPrep does not emit them and the module reads them for stimulus labels and TR.

`golden_master/real/temp.tsv` is a pinned `stimulus_name` to index mapping generated by `gen_label_mapper.py`. Without it, `RealDatasetMixin` rebuilds the mapping at runtime by scanning every raw `events.tsv` in the dataset, which would require shipping all 560 event files instead of six.

## Before publishing a regenerated fixture

`BData.save()` embeds the call stack, including absolute file paths, into `/header` of the `.h5`. `step_5_build_minimal_bundle.sh` strips it with `clean_bdata_header.py`; do not skip that step when publishing, and check the archive for local paths before uploading.
